《Carmessys 汽车制造 MES 系统人机交互界面设计》答辩演讲稿

一、逐页演讲稿

第1页：封面
各位老师好，我们小组汇报的题目是 Carmessys 汽车制造 MES 系统人机交互界面设计。本项目围绕汽车制造现场的生产执行、设备监控、质量追溯、物料物流和数据接入，完成了一个可运行的 MES 仿真系统。我们重点不是单纯做一个好看的页面，而是尝试把课程中的人机交互原则和视觉认知理论，落实到工业场景下的界面设计中。

第2页：整体思路
我们的整体设计逻辑分为四步。第一是场景先行，把系统统一为汽车制造 MES，避免项目主题混乱。第二是角色驱动，因为生产管理员、设备维护员、质量工程师、仓储调度员关注的信息不同。第三是信息分层，从总控看板看全局，到子模块定位问题，再到详情页完成处置。第四是交互闭环，每一个关键动作都要有反馈，并且进入操作日志。

第3页：场景与需求
汽车制造现场的数据来源很多，角色也很多。生产管理员关注产量、OEE、订单完成率和报警数量；设备维护员关注设备温度、振动和停机统计；质量工程师关注 SPC、DPPM、不良率和批次追溯；仓储调度员关注库存安全线和 AGV 物流状态。所以我们希望用一套统一的 MES 执行视图，把 ERP、设备层、WMS、QMS 和现场执行过程连接起来。

第4页：页面结构
这一页是系统页面结构图。最上层是总控看板，用于快速判断生产现场是否正常。中间是业务执行模块，包括工单、设备、质量、物料和 AGV。右侧是数据采集接入，用来模拟 PLC、SCADA、ERP、WMS、QMS 等后端系统进入 MES。底部是权限和日志，用于安全审计和责任追溯。这样的结构体现了从宏观到微观、从监控到处置的层级关系。

第5页：功能与数据流
这一页说明系统的数据流。ERP 提供订单计划，PLC 和 SCADA 提供设备状态数据，WMS 提供库存与物流数据，QMS 提供质量检测数据。数据进入 MES 后，不是简单显示，而是被映射成工单、设备、质量、物料等业务对象，再反馈给不同角色，并写入日志。这样可以体现 MES 在企业系统中的中间层作用，也就是承接计划层和现场控制层。

第6页：总控与工单
总控看板解决的是态势感知问题，所以我们把今日产量、OEE、订单完成率、能耗和报警数量放在首屏最显眼的位置。工单模块解决的是执行推进问题，支持按状态筛选、查看进度，并进入详情页完成工单下发。这里对应课程中的信息层级设计和任务流程设计，让用户先看到关键状态，再进一步处理具体任务。

第7页：设备与质量
设备模块把温度、振动和利用率用阈值颜色表达，正常、预警和高危状态可以快速区分。高危报警可以确认，并生成维护记录。质量模块通过 SPC、CPK、UCL 和 LCL 帮助质量工程师判断过程是否稳定。这两部分都体现了工业实时监控界面中的异常信息突出原则，也能减少用户在复杂信息中的视觉搜索成本。

第8页：物料与数据接入
物料页面体现安全库存和缺料预警，低库存时可以生成补货任务。数据采集页面是我们后续补强的一部分，它模拟 PLC、SCADA、ERP、WMS、QMS 接入 MES。点击“采集一批数据”后，系统会联动总控、设备、库存、质量和日志。这样可以说明我们的系统不是只有静态页面，而是具有一定的信息采集和业务联动逻辑。

第9页：理论映射
本项目不是单纯做界面，而是把 PPT 中的知识点落到系统上。人机交互黄金规则体现在一致性、反馈、错误预防和结束信息。布局原则体现在左侧导航、分区面板和总控看板。数据编码体现在绿色、黄色、红色状态色，大号 KPI 和进度条。视觉认知体现在异常前置和降低认知负荷。动效原则体现在克制地使用状态变化，而不是做装饰性的动画。

第10页：亮点与反思
项目亮点主要有四点：第一，场景统一为汽车制造；第二，页面数量达到 13 页，覆盖课程要求的核心模块；第三，工单下发、报警确认、补货、AGV 调度和数据采集都形成了交互闭环；第四，加入了后端数据采集与接入模拟。不足是目前仍是前端仿真，没有连接真实数据库和真实设备接口；图符体系、多终端适配和真实权限控制还可以继续完善。

第11页：启动教程
演示时可以用四步启动：第一，进入 carmessys 项目目录；第二，首次运行时执行 npm.cmd install 安装依赖；第三，运行 npm.cmd run dev 启动开发服务；第四，浏览器打开终端显示的地址，通常是 http://127.0.0.1:1421。这里使用 npm.cmd，是为了避免 PowerShell 脚本执行策略拦截。也可以双击 start-carmessys.bat 自动启动。

第12页：结束页
以上就是我们的汇报。总体来说，本项目希望用人机交互理论，把复杂的工业数据组织成可理解、可操作、可追溯的现场执行界面。我们对智能制造人机交互的理解是：工业界面不是数据堆叠，也不是越炫越好，而是要服务效率、安全、清晰和抗干扰。感谢老师聆听，欢迎批评指正。


二、技术栈与各软件作用说明

1. Vue 的作用
Vue 是前端界面框架，用来组织页面组件和交互状态。本项目中的左侧导航、总控看板、工单列表、设备卡片、质量图表、物料库存、数据接入页面等，都是通过 Vue 组件化方式实现的。Vue 的好处是页面状态变化比较清楚，例如点击工单下发后，工单状态和日志可以同步更新。

2. TypeScript 的作用
TypeScript 是 JavaScript 的类型增强版本。它可以给工单、设备、物料、AGV、数据源、日志等 mock 数据定义类型，减少字段写错、状态写错的问题。比如设备状态只能是 running、warning、danger 等固定值，工单状态只能在待下发、生产中、质检中、已完成之间变化，这让系统逻辑更稳定。

3. Vite 的作用
Vite 是前端开发和构建工具。开发时，运行 npm.cmd run dev 后，Vite 会启动本地开发服务器，让我们可以在浏览器里实时预览 MES 系统。构建时，运行 npm.cmd run build 后，Vite 会把 Vue 和 TypeScript 代码打包成浏览器可以直接加载的静态文件，输出到 dist 文件夹。简单说，Vite 负责“启动前端”和“打包前端”。

4. Node.js 的作用
Node.js 是运行前端工具链的环境。Vite、TypeScript 编译器、依赖安装工具都需要 Node.js 才能运行。别人如果要打开这个项目，电脑上也需要先安装 Node.js，才能执行 npm.cmd install 和 npm.cmd run dev。

5. npm.cmd 的作用
npm 是 Node.js 的包管理工具，用来安装依赖和执行项目脚本。在 Windows PowerShell 中，直接运行 npm 有时会被脚本执行策略拦截，所以我们使用 npm.cmd。它的作用和 npm 类似，但在 Windows 环境里更稳。比如 npm.cmd install 是安装依赖，npm.cmd run dev 是启动系统，npm.cmd run build 是构建检查。

6. Tauri 的作用
Tauri 是桌面应用外壳，可以把前端网页包装成 Windows 桌面程序。我们参考了原 PCB 项目的打开逻辑：先由 Vite 提供前端页面，再通过 Tauri 使用 Windows WebView2 打开为桌面窗口。这样未来可以把 Carmessys 打包成一个 exe，而不是每次都手动打开浏览器。

7. Rust 的作用
Rust 是 Tauri 底层使用的后端语言。Tauri 的桌面壳、系统窗口、文件权限和打包过程都依赖 Rust 工具链。我们的前端界面主要用 Vue 写，但如果要真正打包成 Windows 桌面程序，就需要 Rust/Cargo 和 Visual Studio Build Tools。也就是说，Rust 不是用来写 MES 页面本身，而是用来支撑 Tauri 桌面程序打包和底层能力。

8. WebView2 的作用
WebView2 是 Windows 上的网页渲染内核。Tauri 打包后的桌面窗口本质上会用 WebView2 来显示前端页面。它的作用可以理解为：让一个网页界面在 Windows 桌面程序窗口中运行。

9. mockData.ts 的作用
mockData.ts 是本项目的集中模拟数据文件。里面存放工单、设备、质量批次、物料、AGV、角色权限、操作日志和后端数据源。因为课程项目不连接真实数据库，所以 mock 数据用来模拟真实 MES 的业务数据。这样既方便演示，也方便后续写 Word 和 PPT。

10. start-carmessys.bat 的作用
start-carmessys.bat 是为普通使用者准备的一键启动脚本。对方如果不熟悉命令行，只要安装了 Node.js，就可以双击这个 bat 文件。它会自动进入项目目录，检查依赖，并启动开发服务器。


三、老师可能会问的问题与参考回答

问题1：为什么选择汽车制造场景，而不是继续沿用 pcb？
回答：因为课程要求选择一个制造业场景，并围绕企业生产流程完成 MES 系统设计。原文件夹里有 pcb 项目，但本项目在新建 carmessys 时统一改为汽车制造场景，是为了避免“文件夹名是 pcb、系统标题是汽车 MES”的主题冲突。汽车制造具有工序多、设备多、质量追溯和物流协同要求高的特点，更适合展示 MES 的综合能力。

问题2：你们的系统和普通数据看板有什么区别？
回答：普通数据看板主要是展示数据，而 MES 更强调生产执行和业务闭环。我们的系统不仅展示 KPI，还能模拟工单下发、设备报警确认、物料补货、AGV 调度和后端数据采集。这些动作会改变页面状态，并写入操作日志，所以它更接近一个 MES 执行模型，而不是静态大屏。

问题3：系统里哪些地方体现了人机交互黄金规则？
回答：一致性体现在统一的导航、卡片、按钮和状态标签；信息反馈体现在点击下发、确认、补货、采集后都有文字反馈和状态变化；错误预防体现在库存正常时禁用补货按钮、无报警时不能确认报警；减轻记忆负担体现在固定左侧导航、模块分区和页面顶部理论提示；结束信息体现在关键操作进入日志，用户知道任务已经完成。

问题4：颜色编码为什么使用绿、黄、红？
回答：这是工业界面中常见的交通灯逻辑。绿色表示正常，黄色表示预警，红色表示高危或报警。它符合用户已有认知习惯，可以减少解释成本，提高异常识别效率。课程 PPT 中也强调数据编码要符合视觉特征和认知习惯。

问题5：你们如何降低认知负荷？
回答：主要通过信息分层、功能分组和异常突出。总控看板只放最关键的 KPI，不把所有信息堆在一起；工单、设备、质量、物料等模块分开，减少跨区域搜索；高危设备、低库存、告警信息用颜色和边界突出，让用户更快定位问题。

问题6：为什么左侧导航适合这个系统？
回答：MES 模块较多，用户需要在总控、工单、设备、质量、物料、数据接入、权限日志之间频繁切换。左侧导航可以保持稳定位置，形成固定心理模型，符合工业信息布局中“左右型布局”和“保持核心稳定”的原则。

问题7：后端数据采集是怎么模拟的？
回答：系统中设置了 PLC、SCADA、ERP、WMS、QMS 五类数据源，分别模拟设备层、监控层、计划层、物流层和质量层数据。点击“采集一批数据”后，会生成一批采集事件，并更新产量、设备温度、库存、质量记录和操作日志。这是前端仿真，不是真实接口，但逻辑上体现了 MES 的数据接入流程。

问题8：为什么要加入操作日志？
回答：工业系统需要可追溯性和安全审计。工单下发、报警确认、补货、AGV 调度、数据采集这些关键动作都应该记录谁在什么时间做了什么。操作日志可以支持责任追溯，也体现了人员权限和安全管理模块。

问题9：Vite 和 Vue 是什么关系？
回答：Vue 是写界面的前端框架，负责组件和交互；Vite 是开发和打包工具，负责启动本地服务、热更新和构建静态文件。可以理解为 Vue 负责“页面怎么写”，Vite 负责“页面怎么跑起来、怎么打包”。

问题10：Rust 在这个项目里起什么作用？
回答：Rust 主要用于 Tauri 桌面壳。我们的 MES 页面本身是 Vue 写的，浏览器运行不需要 Rust。但是如果要像原 PCB 项目一样打包成 Windows 桌面程序，就需要 Tauri，而 Tauri 的底层构建依赖 Rust/Cargo。所以 Rust 的作用是支撑桌面程序打包和底层系统能力。

问题11：如果没有 Rust，系统能不能运行？
回答：能运行。浏览器演示只需要 Node.js、npm.cmd 和 Vite。Rust 只在需要 Tauri 桌面打包时才必须。如果只是课程演示，运行 npm.cmd run dev 就可以打开系统。

问题12：为什么 PowerShell 里要用 npm.cmd？
回答：因为 Windows PowerShell 有脚本执行策略，直接运行 npm 或 npm.ps1 有时会被拦截。npm.cmd 是 Windows 命令形式，通常不会被这个策略影响，所以启动更稳定。

问题13：系统是否连接了真实数据库？
回答：没有。目前是课程仿真系统，使用 mockData.ts 集中管理模拟数据。这样可以完整展示 MES 的页面结构和交互流程。后续如果继续开发，可以把 mock 数据替换成数据库接口或后端 API。

问题14：如果要真正落地，还需要补哪些内容？
回答：需要补真实后端接口、数据库、登录鉴权、角色权限控制、设备通信协议接入、异常处理机制和部署方案。前端方面还可以补图符体系、响应式适配和更完整的数据可视化。

问题15：你们的创新点是什么？
回答：第一是把场景统一为汽车制造，避免主题混乱；第二是页面数量和功能模块比较完整；第三是关键操作都有状态变化和日志闭环；第四是加入了后端数据采集与接入模拟，把 MES 从静态页面推进到信息流联动模型。

问题16：如果老师问这个系统如何体现第四章视觉认知？
回答：第四章讲到视觉搜索、注意捕获、知觉负载和认知负荷。我们的系统用颜色、字号、进度条和分区结构来提高信息显著性，让异常信息更容易被平行搜索发现；同时减少无关装饰，避免信息密度过高造成知觉负载过大。

问题17：SPC、CPK、UCL、LCL 是什么？
回答：SPC 是统计过程控制，用来判断生产过程是否稳定。CPK 是过程能力指数，用来衡量过程满足规格要求的能力。UCL 和 LCL 是控制上限和控制下限，用于判断数据是否超出正常波动范围。我们在质量页面中加入这些指标，是为了体现 MES 的质量过程监控能力。

问题18：OEE 是什么？
回答：OEE 是设备综合效率，通常由可用率、性能效率和质量合格率综合计算。它是制造现场常用的核心指标，用来衡量设备和产线综合利用效果。总控看板中展示 OEE，是为了让管理人员快速判断产线运行水平。

问题19：为什么说“动效要克制”？
回答：工业现场强调安全和效率，过多动画可能造成干扰甚至误操作。我们的系统主要用状态变化、颜色变化、进度变化和日志新增来表达动态，而不是使用大量装饰动画。这符合 PPT 中“动效服务信息，而不是炫技”的原则。

问题20：如果别人要使用这个程序，怎么给他？
回答：可以把整个 carmessys 文件夹发给对方。对方电脑需要安装 Node.js，然后可以双击 start-carmessys.bat，或者在 PowerShell 中进入项目目录，执行 npm.cmd install 和 npm.cmd run dev。如果要做成 exe，则需要继续配置 Tauri、Rust/Cargo、WebView2 和 Visual Studio Build Tools 后再打包。
